4. Bucle: for, while, do-while

O buclă repetă un grup de instrucțiuni. O folosim când nu vrem să scriem aceeași instrucțiune de mai multe ori. Orice buclă trebuie să aibă: pornire, condiție, modificarea variabilei de control și un moment în care se oprește.

for – repetări numărabile

O alegi când știi de câte ori repeți sau când parcurgi indicii unui tablou.

for (int i = 0; i < 5; i++) {
    cout << i << " ";
}
// afișează: 0 1 2 3 4

int i = 0 se execută o singură dată; i < 5 se verifică înaintea fiecărei repetări; i++ se execută după corp.

while – repetări condiționate

O alegi când nu știi dinainte câte repetări vor fi necesare. Condiția se verifică înainte de corp.

int x;
cin >> x;
while (x != 0) {
    cout << "Ai introdus " << x << "\\n";
    cin >> x;
}

Dacă prima valoare este 0, corpul nu se execută deloc.

Greșeli frecvente

  • Buclă infinită: condiția rămâne mereu adevărată, de exemplu uiți să citești o nouă valoare sau să modifici i.
  • O repetare în plus: folosești i <= n când indicii valizi sunt de la 0 la n-1.
  • Punct și virgulă accidental: for (...); are corpul gol; instrucțiunile următoare nu fac parte din buclă.
  • Citire lipsă: în bucla de cereri trebuie citită următoarea valoare, altfel programul poate repeta aceeași cerere.

5. Tablouri unidimensionale

Un tablou (vector) este o zonă de memorie în care păstrezi mai multe valori de același tip. În loc să declari separat bancnota1, bancnota2 etc., folosești un singur nume și accesezi elementele prin indici.

Declarare, inițializare și accesare

const int N = 5;
int v[N] = {4, 7, 2, 9, 1};

cout << v[0]; // primul element: 4
v[2] = 8;     // modifică al treilea element
cout << v[2]; // afișează 8

N reprezintă numărul de elemente, nu ultimul index. Pentru N=5, indicii valizi sunt 0, 1, 2, 3, 4, iar ultimul este întotdeauna N-1.

Foarte important: v[5] este în afara tabloului când ai declarat v[5]. Nu există poziția 5; există pozițiile 0–4. Accesarea în afara limitelor poate produce rezultate imprevizibile.

Citirea și afișarea unui tablou

int v[100], n;
cin >> n;                 // câte elemente folosim
for (int i = 0; i < n; i++)
    cin >> v[i];          // citim pozițiile 0 ... n-1

for (int i = 0; i < n; i++)
    cout << v[i] << " ";  // afișăm aceleași poziții

În acest exemplu, n trebuie să fie cel mult 100. Tabloul are capacitatea 100, dar pot fi folosite doar primele n poziții.

Două tablouri corelate

int valoare[4] = {200, 100, 50, 20};
int stoc[4]    = {  2,   3,  10,  5};

// valoare[2] și stoc[2] se referă la aceeași categorie:
// bancnote de 50 lei, cu stoc de 10 bucăți.

Legătura dintre tablouri este dată de același index. Dacă i este 2, atunci valoare[i] și stoc[i] descriu aceeași categorie. Nu sorta sau reordona un singur tablou separat, fiindcă ai rupe asocierea.

Tablou constant și tablou modificabil

Valorile nominale pot fi declarate const dacă nu trebuie schimbate. Stocul trebuie să rămână modificabil, pentru că se actualizează după tranzacții.

const int valori[4] = {200, 100, 50, 20};
int stoc[4] = {2, 3, 10, 5};

6. Tipare fundamentale pe tablouri

Un tipar este o schemă de instrucțiuni pe care o poți adapta la multe exerciții. În problemele de examen, de multe ori nu trebuie să inventezi algoritmul de la zero: identifici dacă ți se cere o sumă, o numărare, un maxim, o căutare sau o verificare.

1. Parcurgerea – baza tuturor tiparelor

for (int i = 0; i < n; i++) {
    // aici analizezi elementul v[i]
}

i este poziția curentă, iar v[i] este valoarea aflată pe acea poziție. Bucla trece prin fiecare element o singură dată.

2. Sumă – aduni valori

int suma = 0;                 // valoare neutră pentru adunare
for (int i = 0; i < n; i++) {
    suma = suma + v[i];
}

De ce începi cu 0? Pentru că 0 nu schimbă rezultatul adunării. La fiecare pas adaugi elementul curent la totalul deja calculat.

Exemplu: pentru {3, 5, 2}, suma evoluează astfel: 0 → 3 → 8 → 10.

3. Numărare – numeri câte elemente respectă o condiție

int cnt = 0;
for (int i = 0; i < n; i++) {
    if (v[i] % 2 == 0) {
        cnt++;
    }
}

Contorul crește cu 1 doar când condiția este adevărată. Pentru valorile {3, 8, 2, 5}, rezultatul este 2, fiindcă există două numere pare.

4. Maxim și minim – păstrezi cel mai bun candidat

int maxim = v[0]; // pornești de la un element real
for (int i = 1; i < n; i++) {
    if (v[i] > maxim) {
        maxim = v[i];
    }
}

De ce nu pornești obligatoriu cu 0? Pentru că tabloul poate conține doar numere negative. Inițializarea cu v[0] garantează că maximul inițial este o valoare din date. Ai nevoie ca n > 0.

5. Căutare – verifici dacă există o valoare

bool gasit = false;
for (int i = 0; i < n; i++) {
    if (v[i] == x) {
        gasit = true;
    }
}
if (gasit)
    cout << "Exista";
else
    cout << "Nu exista";

bool poate avea doar valorile true sau false. Variabila este un indicator: inițial presupui că nu ai găsit, apoi o schimbi când întâlnești valoarea.

6. Filtrare – prelucrezi doar elementele care trec testul

for (int i = 0; i < n; i++) {
    if (v[i] > 0) {
        cout << v[i] << " ";
    }
}

Filtrarea nu modifică neapărat tabloul; în exemplu doar afișează valorile pozitive.

7. Actualizare – modifici elementul curent

for (int i = 0; i < n; i++) {
    if (v[i] < 0) {
        v[i] = 0;
    }
}

Aici nu doar citești elementele, ci le și schimbi. Fă diferența între o parcurgere de analiză și una de actualizare.

„calculați totalul”, „suma”acumulator

„cel mai mare/mic”maxim/minim

Capcana inițializării: suma și contorul pornesc de la 0; indicatorul pornește de regulă de la false; maximul/minimul pornește dintr-un element al tabloului. Inițializarea depinde de ce calculezi.

8. Strategia greedy

Greedy (algoritm lacom) construiește o soluție pas cu pas. La fiecare pas alege varianta care pare cea mai avantajoasă în acel moment, respectând restricțiile problemei. În mod obișnuit nu revine să schimbe alegerile deja făcute.

Ideea în 4 pași

  1. Stabilești ordinea alegerilor. În problema restului, încerci valorile nominale descrescător: de la cea mai mare la cea mai mică.
  2. Calculezi cât ai putea folosi. Te uiți la câtul dintre suma rămasă și valoarea curentă.
  3. Respecți limitele. Dacă există stoc, nu poți folosi mai multe unități decât ai disponibile.
  4. Actualizezi restul. Scazi valoarea totală folosită și treci la următoarea categorie.

Ce calculezi la o categorie?

Presupunem că:

  • rest = suma care încă trebuie formată;
  • valoare[i] = valoarea unei bancnote/monede;
  • stoc[i] = câte unități sunt disponibile.

Fără limită de stoc, numărul maxim posibil la pasul curent este câtul întreg rest / valoare[i]. Cu stoc limitat, alegerea trebuie să respecte simultan ambele limite:

posibil_din_suma = rest / valoare[i]
posibil_din_stoc = stoc[i]

// cantitatea aleasă nu poate depăși niciuna dintre limite

După alegere, calculezi contribuția categoriei: cantitate_aleasa * valoare[i]. Apoi scazi această contribuție din rest. Nu scazi doar numărul de bancnote; scazi valoarea lor totală.

Exemplu urmărit manual

Ai valori 10, 4 și 1 și trebuie să formezi 27. Alegi 2 unități de 10 (contribuție 20, rest 7), apoi 1 unitate de 4 (contribuție 4, rest 3), apoi 3 unități de 1 (contribuție 3, rest 0).

ValoareRest înainteCantitate aleasăContribuțieRest după
10272207
47143
13330

Greedy nu înseamnă „aleg la întâmplare cea mai mare”

Regula trebuie să fie justificată de problemă. Pentru unele sisteme de valori, alegerea descrescătoare produce o soluție optimă; pentru alte seturi arbitrare, poate produce o soluție neoptimă sau poate să nu găsească o soluție, deși există una prin altă combinație.

De reținut la examen: greedy descrie strategia de alegere, nu rezolvă automat toate restricțiile. Trebuie să verifici și stocul, și suma rămasă, și dacă soluția este completă.

9. Stoc, cereri și actualizare sigură

În această problemă, stocul reprezintă resursele disponibile în acel moment. O cerere este o operație nouă care poate consuma o parte din stoc. Ideea esențială este să nu strici datele inițiale dacă descoperi abia la final că cererea nu poate fi satisfăcută.

Ține separat cele trei tipuri de informații

Variabilă / structurăCe reprezintăCând se modifică?
stoc[i]Resursa reală disponibilă la categoria iNumai după o cerere acceptată
folosit[i] / tablou temporarCantitatea propusă pentru cererea curentăÎn timpul calculului cererii
total[i]Cât s-a folosit cumulat în cererile reușiteDupă acceptarea unei cereri

Nu confunda stocul rămas cu totalul folosit. Dacă ai pornit cu 12 obiecte și ai livrat 3, apoi 4, stocul rămas este 5, iar totalul livrat este 7.

De ce este periculos să modifici stocul imediat?

Imaginează-ți că începi să formezi o cerere și scazi din stoc după fiecare alegere. La final descoperi că suma nu poate fi formată complet. Dacă afișezi „cerere imposibilă”, dar ai scăzut deja câteva bancnote din stoc, datele au devenit incorecte. Următoarea cerere va porni de la un stoc fals.

Exemplu de eroare logică: cererea consumă temporar 2 bancnote dintr-o categorie, apoi algoritmul constată că restul nu poate fi acoperit. Dacă stocul real a fost deja micșorat, ai pierdut acele 2 bancnote chiar dacă operația a eșuat.

Metoda sigură: propunere, verificare, confirmare

  1. Propunere: creezi un tablou temporar pentru cantitățile pe care ai vrea să le folosești. Stocul real rămâne neatins.
  2. Verificare: parcurgi categoriile și calculezi dacă poți acoperi toată cererea. Urmărești suma rămasă.
  3. Decizie: dacă la final restul este diferit de 0, cererea eșuează. Nu transferi nimic din propunere în stoc.
  4. Confirmare: doar dacă restul este 0, scazi cantitățile propuse din stocul real și le adaugi la totalurile folosite.
// Schemă conceptuală – nu este soluția completă a subiectului
int propus[7] = {0};

// 1. Calculezi în propus[], fără să modifici stoc[].
// 2. Verifici dacă cererea a fost acoperită integral.

if (cerere_acoperita) {
    // 3. Confirmi: actualizezi stocul real și totalurile.
} else {
    // 4. Respingi: stocul real rămâne neschimbat.
}

Invariantă: regula care trebuie să rămână adevărată

După fiecare cerere procesată, pentru fiecare categorie trebuie să fie adevărat că:

  • stocul rămas nu este negativ;
  • stocul rămas + cantitatea consumată = stocul inițial;
  • totalurile cresc numai pentru cererile acceptate;
  • o cerere respinsă nu schimbă stocul și totalurile.

Aceste reguli se numesc invariante: condiții care trebuie să rămână adevărate pe parcursul programului. Sunt foarte utile pentru a verifica dacă algoritmul este corect.

Exemplu cu două cereri

La început ai 5 unități în stoc. Prima cerere folosește 2 și este acceptată: stocul devine 3, totalul folosit devine 2. A doua cerere ar necesita 4, dar ai doar 3. A doua cerere este respinsă: stocul rămâne 3, iar totalul folosit rămâne 2.

MomentStocTotal folositObservație
Inițial50Nu s-a procesat nimic
După cererea 132Acceptată
După cererea 232Respinsă, fără modificări

Ordinea validării unei cereri

  1. Citești valoarea cererii.
  2. Dacă este 0, oprești procesarea – este valoarea de terminare.
  3. Dacă este negativă, afișezi mesaj de eroare și treci la următoarea cerere.
  4. Dacă este pozitivă, calculezi propunerea folosind stocul disponibil.
  5. Dacă nu poți acoperi integral cererea, o respingi fără actualizări.
  6. Dacă o poți acoperi, confirmi actualizarea stocului și a totalurilor.
Ideea de memorat: întâi simulezi tranzacția, apoi o confirmi. Este aceeași idee folosită în multe programe reale: o operație trebuie să fie complet validă înainte să schimbe datele permanente.

Teorie aprofundată – înțelege ce calculezi și de ce

Această parte completează lecțiile de bază fără să schimbe exercițiile, testele sau compilatorul. Scopul este să înțelegi raționamentul din spatele fiecărei instrucțiuni, nu doar să recunoști sintaxa.

11.1. Cum se execută un program C++

Un program C++ este executat în ordine, de sus în jos, începând cu funcția main(). Instrucțiunile dintr-un bloc delimitat de acolade se execută atunci când fluxul ajunge la acel bloc. O condiție poate sări peste un bloc, iar o buclă poate relua un bloc de mai multe ori.

int x = 4;       // 1. se creează x și primește valoarea 4
x = x + 3;       // 2. se calculează 4 + 3, apoi x devine 7
cout << x;       // 3. se afișează 7

În expresia x = x + 3, partea din dreapta se calculează prima. Rezultatul este apoi atribuit variabilei din stânga. Semnul egal din programare nu este o ecuație matematică; el înseamnă „pune în variabila din stânga rezultatul din dreapta”.

Metodă de urmărire: citește codul linie cu linie și notează valorile variabilelor după fiecare instrucțiune. Această tehnică se numește urmărire manuală sau dry run.

int rezultat = 10 + 6 * 2;     // 22, nu 32

11.3. Ce înseamnă câtul și restul – explicație pas cu pas

Pentru două numere întregi pozitive a și b, există relația:

a = (a / b) * b + (a % b)

De exemplu, pentru a = 29 și b = 6:

  • 6 încape de 4 ori complet în 29;
  • 4 × 6 = 24;
  • 29 − 24 = 5;
  • deci 29 / 6 este 4, iar 29 % 6 este 5.

Restul este întotdeauna mai mic decât împărțitorul pentru numere pozitive. Dacă restul este 0, împărțirea este exactă.

La ce te ajută % în probleme?

  • Paritate: n % 2 == 0 înseamnă număr par.
  • Ultima cifră a unui număr pozitiv: n % 10.
  • Eliminarea ultimei cifre: n / 10 pentru int pozitiv.
  • Verificarea divizibilității: n % d == 0, cu condiția ca d să nu fie 0.
Nu împărți niciodată la zero. Expresiile a / 0 și a % 0 nu sunt valide.

11.6. Tablourile – memorie, index și legătura dintre poziții

Un tablou de dimensiune N rezervă spațiu pentru exact N elemente de același tip. Numele tabloului identifică zona de memorie, iar indexul selectează un element.

int note[4] = {8, 9, 10, 7};
cout << note[0]; // primul element: 8
cout << note[3]; // ultimul element: 7

De ce începe indexul de la 0? Indexul reprezintă distanța față de primul element: primul este la distanța 0, al doilea la distanța 1 și așa mai departe. De aceea, pentru N elemente, ultimul index este N−1.

Ce înseamnă depășirea limitelor?

Dacă ai int v[4], pozițiile valide sunt 0, 1, 2 și 3. Accesarea lui v[4] este în afara tabloului. C++ nu garantează un mesaj de eroare; programul poate afișa valori imprevizibile sau se poate comporta incorect. Verifică întotdeauna limitele.

Două tablouri sincronizate

Imaginează-ți că ai un tablou cu denumiri de produse și altul cu stocurile. Poziția 0 din primul tablou trebuie să descrie aceeași categorie ca poziția 0 din al doilea. Dacă sortezi sau modifici ordinea unui tablou fără să păstrezi asocierea, datele nu mai corespund.

Regulă practică: când două tablouri descriu aceeași listă de categorii, parcurge-le cu același index i. denominatii[i], stoc[i] și totalOferit[i] se referă toate la categoria de pe poziția i.

11.7. Tipare de calcul pe tablouri – cum gândești inițializarea

Sumă: începi cu 0 pentru că încă nu ai adunat nimic. Apoi adaugi fiecare element.

int suma = 0;
for (int i = 0; i < n; i++)
    suma = suma + v[i];

Contor: începi cu 0 pentru că încă nu ai numărat nicio apariție. Crești contorul doar când condiția este adevărată.

int cnt = 0;
for (int i = 0; i < n; i++)
    if (v[i] > 0) cnt++;

Maxim: inițializezi cu primul element, nu cu 0, deoarece toate valorile ar putea fi negative. Apoi înlocuiești maximul când găsești ceva mai mare.

int maxim = v[0];
for (int i = 1; i < n; i++)
    if (v[i] > maxim) maxim = v[i];

Indicator boolean: pornești cu false pentru „încă nu am găsit”. Când găsești elementul căutat, îl setezi la true.

În tiparul pentru maxim, tabloul trebuie să aibă cel puțin un element. Dacă n poate fi 0, trebuie tratat separat înainte de a accesa v[0].

11.8. Greedy în profunzime – ce calculezi la fiecare pas

Un algoritm greedy construiește soluția treptat. La fiecare pas:

  1. Identifici opțiunea curentă, de exemplu valoarea de pe poziția i.
  2. Calculezi limita impusă de ținta rămasă.
  3. Calculezi limita impusă de resursele disponibile.
  4. Alegi cantitatea care respectă ambele limite.
  5. Calculezi contribuția acestei alegeri la suma formată.
  6. Scazi contribuția din ținta rămasă și treci la următoarea opțiune.

Într-o problemă de formare a unei sume, dacă valoarea curentă este d, ținta rămasă este R, iar stocul este S, cantitatea aleasă nu poate fi mai mare decât R / d și nici decât S. De aceea apare ideea de minim dintre cele două limite.

limita_din_suma = R / d;
limita_din_stoc = S;
cantitate_aleasa = minimul celor doua;
valoare_acoperita = cantitate_aleasa * d;
R = R - valoare_acoperita;

Acestea sunt relațiile matematice ale pasului greedy, nu rezolvarea completă a simulării. După ce parcurgi toate valorile, dacă R este 0, ținta a fost formată. Dacă este pozitiv, nu ai reușit să o formezi cu resursele disponibile.

Întrebare de control: de ce nu alegi mai multe unități decât R / d? Pentru că ai depăși suma rămasă. De ce nu alegi mai multe decât stocul? Pentru că ai folosi resurse care nu există.

11.9. De ce trebuie calculată întâi o propunere temporară?

Gândește cererea ca pe o tranzacție. O tranzacție are două rezultate posibile: confirmată sau anulată. Dacă actualizezi stocul real în timp ce încă verifici dacă poți forma suma, o cerere imposibilă poate consuma parțial resurse.

Varianta riscantă

Scazi imediat din stoc pentru fiecare categorie. La final descoperi că nu ajunge. Acum trebuie să refaci toate scăderile și riști să uiți una.

Varianta sigură

Calculezi într-un tablou temporar. Dacă reușești, aplici toate scăderile. Dacă nu, ignori propunerea temporară și stocul rămâne intact.

Separarea calculului de confirmare face programul mai ușor de verificat și reduce erorile logice. Este o idee folosită și în aplicații reale, nu doar în exerciții de facultate.

11.11. Erori de compilare versus erori logice

Eroare de sintaxă / compilare

Compilatorul nu poate transforma codul într-un program executabil. Exemple: punct și virgulă lipsă, acolade neînchise, variabilă nedeclarată, paranteze greșite.

Eroare logică

Programul compilează și rulează, dar rezultatul este greșit. Exemple: folosești i <= n în loc de i < n, modifici stocul prea devreme sau uiți să resetezi o variabilă pentru cererea următoare.

Compilatorul te ajută să găsești erorile de sintaxă. Testele și urmărirea manuală te ajută să găsești erorile logice.

11. Exemple C++ care se pot compila

Exemplul de mai jos citește 5 numere, calculează suma și numără valorile pare. Apasă „Trimite în compilator” pentru a-l încărca în editor.

#include <iostream>
using namespace std;
int main() {
    int v[5], suma = 0, pare = 0;
    for (int i = 0; i < 5; i++) {
        cin >> v[i];
        suma += v[i];
        if (v[i] % 2 == 0) pare++;
    }
    cout << "Suma = " << suma << '\\n';
    cout << "Pare = " << pare << '\\n';
    return 0;
}

Intrare de test pentru exemplu: 2 5 8 1 4. Rezultatul așteptat: suma 20, numere pare 3.

16. Plan de atac pentru simularea profesorului

  1. Definește tabloul constant al denominațiilor, în ordinea cerută.
  2. Citește stocul într-un al doilea tablou, păstrând aceeași poziție pentru aceeași categorie.
  3. Pregătește tabloul totalurilor oferite.
  4. Citește cereri repetate până la 0; tratează negativul separat.
  5. Pentru fiecare cerere, calculează cantitățile propuse într-un tablou temporar.
  6. Verifică dacă suma a fost acoperită complet.
  7. Doar la succes actualizează stocul și totalurile oferite.
  8. La final afișează fiecare denominație, totalul oferit și stocul rămas.
Nu copia o rezolvare gata făcută. Profesorul poate schimba valorile, numărul de categorii sau condițiile. Dacă stăpânești tiparele de mai sus, vei putea adapta algoritmul.

Checklist înainte de predare

  • Nu accesez niciodată un index în afara tabloului.
  • 0 oprește programul și nu este procesat ca rest.
  • Negativul afișează eroare și citirea continuă.
  • O cerere imposibilă nu modifică stocul.
  • Totalurile se modifică doar pentru cereri reușite.
  • Raportul final include toate denominațiile.
  • Am testat și cazul fără nicio cerere.
